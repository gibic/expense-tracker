Two app tables, `expenses` and `categories`, are each owned by a user through `user_id`, a `text` foreign key to Better Auth's `user` table. Better Auth's own tables (`user`, `session`, `account`, `verification`) are generated by its CLI and not designed here; see the [core schema docs](https://www.better-auth.com/docs/concepts/database).

## expenses

| Column        | Type          | Rules                                                        |
| ------------- | ------------- | ------------------------------------------------------------ |
| `id`          | `uuid`        | Primary key, generated by the database                       |
| `user_id`     | `text`        | Not null, foreign key to `user.id`                           |
| `category_id` | `uuid`        | Not null, foreign key to `categories.id`, on delete restrict |
| `amount`      | `bigint`      | Not null, whole rupiah, greater than 0                       |
| `date`        | `date`        | Not null, the day the money was spent                        |
| `note`        | `text`        | Optional                                                     |
| `created_at`  | `timestamptz` | Not null, defaults to now()                                  |

The restrict rule on `category_id` is what blocks deleting a category that still has expenses. There is no cascade from `user_id` because v1 has no account deletion flow.

## categories

| Column       | Type          | Rules                                  |
| ------------ | ------------- | -------------------------------------- |
| `id`         | `uuid`        | Primary key, generated by the database |
| `user_id`    | `text`        | Not null, foreign key to `user.id`     |
| `name`       | `text`        | Not null, unique per user              |
| `created_at` | `timestamptz` | Not null, defaults to now()            |

Each user gets a seeded default set: Food & drinks, Transport, Bills & utilities, Shopping, Health, Entertainment and Other.

## Indexes and constraints

- `expenses (user_id, date)`: serves the month list and the month totals.
- `expenses (category_id)`: serves the "category in use" check; Postgres does not index a foreign key on its own.
- `categories (user_id, name)`, unique: no duplicate category names for one user.
- `expenses.amount > 0`, as a check constraint: matches the form rule that blocks zero or negative amounts.

## Month queries

Both queries filter by `user_id` and by the month as a range: from the first day of the month, up to but not including the first day of the next.

- **Month total:** the sum of `amount`.
- **Per-category breakdown:** the sum of `amount` grouped by `category_id`, joined to `categories.name`.

`date` is a plain date with no time zone, so month boundaries do not shift with the server's time zone.

## Decisions

- **Seed set:** Food & drinks, Transport, Bills & utilities, Shopping, Health, Entertainment and Other. Each user can rename, add or delete categories afterwards.
- **Seeding:** a Better Auth `databaseHooks.user.create.after` hook inserts the set once, at sign-up (`db/seed.ts`). A failed seed is logged and not retried; `seedDefaultCategories` is safe to call again. A user who deletes every category keeps an empty list.
- **`updated_at`:** not added in v1. No flow shows a last-edited time; add it with a migration if one is needed.
